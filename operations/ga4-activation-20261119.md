# ガジェット比較サイトの GA4 有効化（2026-11-19）

ユーザーが作成したガジェットサイト専用のWebデータストリームの測定ID
`G-1273VEC9JB` を `config/analytics.json` に設定した。測定IDは公開識別子で
APIキーやパスワードではない。別サイトのストリームを流用しない。

## 実装済みのイベント

`scripts/build_site.py` はビルド時に全ページで以下を出力する。

- Googleタグ（gtag.js）を1回読み込み、`gtag("config", "G-1273VEC9JB")`
  により通常の `page_view` を計測する。
- 楽天の商品画像、商品名、購入ボタン、比較表のリンククリックで
  `affiliate_click` イベントを送信する。
- イベントパラメータ: `item_code`, `item_category`, `link_placement`,
  `link_target=rakuten`。楽天の元URLは改変も送信もしない。
- クリックした人のナビゲーションを妨げず、分析通信に失敗しても購入導線を止めない。

Google Analyticsの「拡張計測機能」により、別名の標準イベント
`click` が発生する可能性がある。**`affiliate_click` と `click` を
別人のクリック数として合算しない。** `affiliate_click` は購入や報酬の
事実を表すイベントではない。実際の売上は楽天側の公式成果レポートで確認する。

## GA4での確認（公開後）

1. 本番 GitHub Pages の新しい `Publish Pages` ステップが `success`
   であることを確認し、更新された公開HTMLのタグを確認する。PRのCI成功
   だけで稼働開始と判断しない。
2. PCでガジェットサイトを実際に表示。GA4の「レポート → リアルタイム」
   に `page_view` が受信されることを確認する。
3. 自分でテスト商品から楽天のリンクを1回クリックし、GA4のイベントに
   `affiliate_click` が現れるか確認する。購入は不要。
4. 分析に必要なら、GA4の「管理 → データの表示 → カスタム定義」で
   **イベントスコープ**のカスタムディメンション
   `item_category` と `link_placement` を登録。
   個別商品コード `item_code` は高カーディナリティを招くため任意とする。
   カスタム定義は作成前の値に遡って反映されない場合がある。

GA4への実際の送信・受信は利用者のブラウザー設定・広告ブロッカーや
Cookie制限に左右される。サイトの公開前にはGA4が受信しないのが正常。
リアルタイムレポートの数値がすぐに表示されない場合もある。

## 安全性と既存運用

- Analytics IDの設定とプライバシー表示、オフラインテストのみを変更。
- 楽天APIの資格情報、Affiliate IDの期限付き暫定モード、
  Windowsの定期収集時刻、商品の価格履歴、note自動投稿は変更しない。
- 既存ワークフローは1日1回の本番公開を守る。GA4だけのために二重投稿や
  強制再公開をせず、次の**実際の正常なPagesデプロイ**で反映する。
- `scripts/test_ga4_activation.py` は実環境へのAPI通信を行わずに、
  測定ID、挿入回数、リンククリックイベントを検査する。
